# Content and behaviour preservation map

Baseline: 27 root HTML files, read on 23 September 2026. `research/site-audit.json` stores headings, body text, local IDs, form fields, image references, and links for every page. Inline JavaScript-generated content, particularly homepage applications and the API-backed store, must also be migrated from their source modules.

- `instruments.html#oscilloscopes`, `#power`, `#rf`, `#production`

The source audit found these missing IDs across links from 26 or 27 pages per target. It found no missing local files among HTML `href` links. That is not a claim that every image, remote URL, API, or runtime interaction was tested.

## Primary journeys

1. **Known part / component:** Components or Store → family/search → brand or product → technical facts → quantity purchase or contextual RFQ.
2. **Known instrument:** Instruments → type → manufacturer/product → application fit → request a demo or quotation.
3. **Known application:** Applications → relevant system → component/test requirements → matching brands → contextual enquiry.
4. **Supplier evaluation:** Brands/About → company capabilities and relevant division → manufacturer partnership enquiry.
5. **Returning buyer:** Search or saved deep link → same route/context → details and next action, without replaying a product introduction.

## Behaviour contracts

- Keep enquiry parameter aliases used today: `brand=ea`, `wxdh`, `jilin`, `motinmark`, `mlccbase`, `unit`, etc.; map them to the canonical brand data. Do not assume route slugs equal query values.
- Preserve form field names and validation requirements. Populate context visibly and carry it to the server. If BOM upload is added, implement actual accepted file types, size feedback, server receipt and email attachment handling before calling the action “Upload BOM”.
- Retain `silicom-cart` data or provide a deliberate migration. Preserve currency, quantity breaks, API-driven inventory, and server-calculated totals.
- Keep `/api`, `/admin`, store-upload URLs, and their operational behaviour. Store tests must use test data/payment mode.
- Migrate page titles, descriptions, canonical links, social metadata, sitemap, robots rules and relevant structured data. Preserve factual content rather than keyword repetition.
- Maintain keyboard focus, active/expanded states, direct anchor navigation, phone/email links, loading/error/empty states and reduced-motion behaviour.

## Content parity gate

During migration, each source block receives a destination route/section and one status: retained, condensed with facts retained, relocated with a link, or requires factual confirmation. No unclassified content block may be silently dropped. The current audit is the baseline; completion requires a comparison against the new rendered pages and dynamically supplied content.
